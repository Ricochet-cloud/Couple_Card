# 추억카드뽑기 웹사이트 PRD (v1.2)

> 우리 둘만의 추억을 카드로 모으는 작은 웹사이트. 복잡하지 않게, 꼭 필요한 기능만.

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 뽑기권 | 하루 1장 자동 지급 + 관리자가 추가 지급 가능 |
| 중복 카드 | 허용 (보유 수량만 카운트) |
| 등급 | 울트라 / 전설 / 신화 / 영웅 / 초희귀 / 희귀 (6단계) |
| 도감 | 포켓몬 도감 방식: 번호 순 배열, 뽑으면 등록, 미보유는 실루엣 |
| 초기 카드 수 | 50장 내외 |
| 계정 | 관리자(나) 1 + 공용 1, 회원가입 없음 |
| 스택 | HTML/CSS/순수 JS + Firebase, 모바일 우선 반응형 |

## 2. 목표

- 함께한 추억(사진 + 한 줄 설명)을 카드로 만들고 뽑기로 하나씩 꺼내보는 재미를 준다.
- 매일 들어와서 뽑기 1회, 미션 1개를 하는 가벼운 습관을 만든다.
- 관리자가 코드 수정 없이 카드, 미션, 뽑기권을 관리한다.

**성공 기준**: 모바일/PC에서 로그인 → 뽑기 → 도감 확인이 막힘없이 되고, 새 카드를 관리자 페이지에서 5분 안에 추가할 수 있다.

## 3. 사용자와 계정

| 계정 | 사용자 | 권한 |
|---|---|---|
| 관리자 | 나 | 뽑기·도감·미션 + 관리자 페이지 |
| 공용 | 여자친구 | 뽑기·도감·미션 (관리자 페이지 접근 불가) |

- Firebase Authentication 이메일/비밀번호, 계정 2개를 직접 생성
- 관리자 판별은 관리자 UID를 보안 규칙에 지정
- 뽑기권, 도감, 미션 진행 상태는 **둘이 하나를 공유**

## 4. 핵심 기능

### 4-1. 뽑기권
- 하루 1장 자동 지급: 그날 첫 접속 시 한국 시간(KST) 기준으로 지급 (`lastGrantDate`로 하루 1회만)
- 쓰지 않은 뽑기권은 쌓인다 (가정, 5번 참고)
- 관리자 페이지에서 "뽑기권 +N" 추가 지급

### 4-2. 카드뽑기
- 뽑기권 1장 사용 → 활성 카드 중 1장 획득
- **등급 먼저 추첨 → 해당 등급 카드 중 랜덤** 방식 (등급 확률이 카드 수와 무관하게 유지됨)
- 초기 확률안 (등급 순서는 아래 표 기준, 설정 파일에서 수정):

| 등급 | 확률 |
|---|---|
| 울트라 | 2% |
| 전설 | 5% |
| 신화 | 8% |
| 영웅 | 15% |
| 초희귀 | 30% |
| 희귀 | 40% |

- 이미 가진 카드도 나올 수 있고 수량이 +1
- 결과 화면: 카드 뒤집기 연출, 처음 얻은 카드에는 NEW 표시, "도감 보기 / 한 번 더(권 있을 때)" 버튼
- 등급이 높을수록 연출을 살짝 키움 (CSS 효과만)

### 4-3. 도감 (포켓몬 도감 스타일)
- 카드마다 **도감 번호**(No.001~)를 부여해 번호 순으로 그리드 표시
- 미보유: 실루엣 + "No.012 ???", 보유: 원본 카드
- 상단 수집률 "23 / 50", 등급별 수집 현황
- 필터: 등급, 분류, 보유/미보유 / 정렬: 번호순(기본), 획득순
- 카드 탭 → 상세 (큰 사진, 설명, 추억 날짜, 처음 얻은 날, 보유 수량)

### 4-4. 일일 미션
- 하루 1개 자동 배정 (KST 날짜 변경), 안 나온 미션 위주로 랜덤, 소진되면 순환
- "완료" 체크 (하루 1회). 뽑기권과는 독립 (가정, 5번 참고)

### 4-5. 관리자 페이지 (`admin.html`)
- **카드 관리**: 추가, 수정, 비활성/삭제, 사진 업로드, 도감 번호 지정
- **미션 관리**: 추가, 수정, 비활성
- **뽑기권 지급**: +N 버튼
- 저장 즉시 사이트에 반영 (배포 불필요)

## 5. 카드 템플릿

```html
<article class="card" data-rarity="legend">
  <span class="card__no">No.{dexNo}</span>
  <div class="card__photo"><img src="{photoUrl}" alt="{title}"></div>
  <div class="card__body">
    <span class="card__badge">{rarityLabel}</span>
    <h3 class="card__title">{title}</h3>
    <p class="card__desc">{description}</p>
    <footer class="card__meta">{category} · {memoryDate}</footer>
  </div>
</article>
```

- 등급 키: `ultra / legend / myth / hero / superrare / rare` (화면 표시는 한글 라벨)
- 등급별 테두리·광택은 `data-rarity` 속성으로 CSS에서만 관리
- 카드 비율 고정(5:7), 사진은 `object-fit: cover`

## 6. 데이터 모델 (Firestore)

```
cards/{cardId}
  dexNo (유니크 숫자), title, description, photoUrl,
  rarity, category, memoryDate, active, createdAt

missions/{missionId}
  text, active, createdAt

state/shared                 // 둘이 공유하는 진행 상태
  tickets: number
  lastGrantDate: "2026-10-05"
  owned: { cardId: { count, firstAt } }
  daily: { date, missionId, done }
  usedMissionIds: [ ... ]
```

- 뽑기, 권 지급, 권 차감은 **트랜잭션**으로 처리해 중복 지급/중복 사용 방지
- **사진 저장**: Firebase Storage는 Blaze(종량제, 카드 등록 필요) 요금제에서만 쓸 수 있어서, 무료(Spark) 유지를 위해 **압축한 사진을 카드 문서에 데이터(`photoData`, base64)로 직접 저장**한다. 업로드 시 브라우저에서 긴 변 640px 이하 WebP로 변환 (장당 약 30~60KB, Firestore 문서 한도 1MiB에 한참 여유)
- 50장 기준 도감 로딩 시 약 2~3MB. Firestore 로컬 캐시를 켜서 재방문 시 다시 받지 않게 한다
- 나중에 카드가 크게 늘면 Blaze로 올리고 Storage로 이전 가능

## 7. 보안 규칙 (요약)

- Auth는 이메일/비밀번호지만 API 키가 공개되므로 **남이 계정을 만들 수 있다**. 따라서 규칙은 "로그인했는가"가 아니라 **허용된 UID 2개(관리자, 공용)만 허용**하는 방식으로 쓴다
- `cards`, `missions`: 두 UID 읽기 가능, 쓰기는 관리자 UID만
- `state/shared`: 두 UID 모두 읽기/쓰기 (둘만 쓰는 사이트라 필드 단위 검증은 하지 않음)
- 그 외 모든 경로는 거부
- Firebase 콘솔 Authentication 설정에서 신규 가입 차단도 가능하면 켠다

## 8. 화면 구성

GitHub Pages는 `/admin` 같은 경로 리다이렉트를 지원하지 않으므로 **화면마다 HTML 파일을 따로** 둔다. 모든 링크는 상대 경로를 쓴다 (저장소 이름이 URL 일부가 되기 때문).

| 화면 | 파일 | 내용 |
|---|---|---|
| 로그인 | `login.html` | 이메일/비밀번호 |
| 홈 | `index.html` | 보유 뽑기권, 오늘의 미션, 뽑기 버튼, 최근 획득 |
| 뽑기 | `draw.html` | 뒤집기 연출 + 결과 |
| 도감 | `collection.html` | 번호순 그리드, 필터, 상세 모달 |
| 관리자 | `admin.html` | 카드 / 미션 / 뽑기권 탭 |

하단 탭(홈 · 도감) + 관리자에게만 보이는 관리 메뉴.

## 9. 기술 스택

- **프론트엔드**: HTML / CSS / 순수 JavaScript (ES Modules), 빌드 도구 없음
- **백엔드**: Firebase Authentication, Firestore (Storage는 사용하지 않음)
- **배포**: GitHub Pages (공개 저장소, main 브랜치 루트)
- **반응형**: 모바일 우선, CSS Grid(`auto-fill, minmax`)로 열 수 자동 조절, 터치 영역 최소 44px, 카드 뒤집기는 CSS 3D transform

## 10. MVP 범위

**포함**: 로그인, 일일 뽑기권, 뽑기, 도감, 일일 미션, 관리자(카드/미션/뽑기권), 반응형

**제외**: 회원가입, 푸시 알림, 카드 교환, 업적/랭킹, 다크모드, 천장(확정 등급) 시스템

## 11. 개발 단계

1. Firebase 프로젝트 생성, 계정 2개 등록, 보안 규칙 적용
2. 카드 템플릿 + 6개 등급 스타일 완성
3. 관리자 페이지: 카드 추가·수정·사진 업로드
4. 도감 화면 (번호순, 실루엣, 필터)
5. 일일 뽑기권 + 뽑기 로직 + 연출
6. 일일 미션
7. 관리자 뽑기권 지급
8. 모바일 실기기 테스트 후 배포

## 12. 남은 확인 사항

1. **등급 서열**: 위 확률표는 말씀하신 순서(울트라 > 전설 > 신화 > 영웅 > 초희귀 > 희귀)를 높은 등급부터로 가정했어요. 순서가 다르면 알려주세요.
2. **뽑기권 누적**: 안 쓴 권이 쌓이는 걸로 가정했어요. 매일 1장만 쓰고 소멸시킬지 정해주세요.
3. **미션과 뽑기권**: 미션은 뽑기권과 별개의 "오늘의 재미"로 가정했어요. 미션 완료 시 보너스 권을 주고 싶다면 알려주세요.
4. **미션 기록**: 단순 완료 체크로 충분한지, 사진/메모를 남기고 싶은지.
